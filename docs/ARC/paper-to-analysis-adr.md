# ADR：论文能力归属与第一条证据链

日期：2026-10-17；状态：提出，离线验证范围已采用，平台接入未实施。

## 背景

附件要求完整 Paper-to-Data-to-Analysis，代码调查确认主平台已经实现 PDFProcessor、FileRecord、Dataset、ResearchPlan、Gateway、FlowFrame 与报告证据链。寻宝鼠 Node runtime 是检索执行器，React island 是 Vue 的展示组件；不能在子仓再造上传存储、权限、队列和流程引擎。平台 Agent 下载/分析写门禁尚未通过。

## 决策

1. 大文件和解析任务由平台所有者/项目鉴权后，经现有队列调用 PDFProcessor。PDFProcessor 的超限 fallback 不是拒绝机制；入口须在调用前拒绝超限。
2. 文献标识解析、全文获取、结构解析、数据核验、科学规划、任务执行各自分层。先构建无 I/O 的页证据与编号索引，外加仅供本地显式运行的 PDF 适配 CLI；不开放未经认证的 Node 上传路由。
3. 证据 ID 绑定文件摘要、页号与字符范围；正文保持解析器原始文本，片段必须可反查。没有图表坐标时保持 null，章节识别仅为启发式，不捏造版面定位。编号仅记“原文提及，未核验”，不自动晋升“论文原始数据”。
4. 计划继续复用 `cygnusx.research_plan.v1`，科学方法说明与证据单独随 revision 绑定。编辑使摘要和审批失效。论文服务不得在模型建议或 PDF 文本指令下提交任务。
5. 只有现有平台真实执行门禁通过、用户明确批准当前摘要、Dataset handoff 已验证、资源/权限复验后，才可复用 submit；本任务不绕过或关闭门禁。
6. 首轮不增加 GROBID/Docling，不新增 Agent/MCP，不把缺失后端做成模拟 API。首页保留四卡；文案升级和上传控件应与真实入口同步发布，避免展示当前不可用的能力。

## 影响

主平台需要新增项目级 PaperDocument / PaperRevision 及解析任务，复用文件/产物实体。Vue 维护认证、上传、轮询与版本；React 仅接收非敏感 view model 和 action。Node 可继续复用公开只读检索，不管理论文所有权。独立 SPA 后续须明确与平台功能可用性的差异。

## 验证与替代

离线 CLI 可以证明真实 PDF 解析和原文提及索引，不能证明上传 API、异步任务、数据库核验、深度解读或分析执行。直接给 Node 加 PDF 上传虽容易演示，但会产生第二套文件权限/任务系统，予以否决。另写 PDF parser 会重复现有适配器，予以否决。平台缺少的写运行验收必须单独完成后再进入端到端验收。
