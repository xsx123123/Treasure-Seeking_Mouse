### 1.2 判为「刻意约束」而非缺口（不转待办，对外措辞保留）

- GEO-only 项目返回空而非报错（`emptyStudyResult()`，docs/ARC/README 硬红线）；
- 下载推荐不进正文、只走卡片（提示词规则 9-10 + DownloadBoostCard）；
- 提示词外置 + sync-prompts 漂移测试；
- Google Scholar 仅出站链接不抓取。
- crawler/ 空骨架（R11）与冻结副本漂移（R12）：不进本计划，建议单独立"仓库卫生"小任务（删或归档 qmuse/、weixin/ 若不再维护），避免与架构优化混在一起。

### 1.3 行动顺序（不照搬报告排期，按止血前置 + 叙事价值排序）

```
阶段 0  止血前置包（安全 + 校验对称性）        ← 必做，改动小，1 天内
阶段 1  查不准：正文↔证据硬校验 + 回溯核验      ← 叙事价值最高，V1 论文核心卖点
阶段 2  查不到：意图翻译层代码化（IR + 测试）    ← 让"意图翻译"从叙事变成可演示能力
阶段 3  查得慢：ENA/GSA/降级兜底/跨源编排       ← 工程量最大，可 V1 投出后迭代
```

排序理由：阶段 0 是安全面，不受叙事排期影响；阶段 1 直接补"查不准"最硬的缺口
（R3 + 正文↔证据不绑定），且全部改动集中在 `index.ts` 主循环收尾段与前端一个组件，
风险可控、e2e 可验；阶段 2 建立 IR 模块后会改变提示词与主循环结构，放在阶段 1 之后
避免两拨改动互相纠缠；阶段 3 涉及外部 API 接入与单点依赖改造，最慢，放最后。

## Part 二　总策略与共同纪律

- **不推翻现有架构，渐进增强**：`executeTool` switch 保留；新能力以"校验/旁路/新工具"
  形式挂进去，不重构主循环骨架。
- **每个新能力必须带测试**，对照 `tests/resolveStudy.test.ts` 黄金用例模式——
  调查报告已证明这是本项目守护复杂逻辑的有效范式。
- **SSE 协议只加不改**：新事件类型（如 `grounding`）增量添加，现有 `delta/tool/cards/end`
  帧格式不动，前端旧版本不崩。
- **提示词改动必须走 `sync:prompts` + `tests/prompts-sync.test.ts` 漂移测试**。
- **对外叙事同步**：每完成一个阶段，论文/BP 相应句子的措辞从"规划中/目标"升级为
  "已实现"，并更新 docs/architecture.md 架构图（灰色虚框转实线）。
